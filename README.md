## ✅ AI 产品评测检查清单

评测前先明确用户、任务和成功标准，再用固定样例比较不同方案。以下是后续项目可复用的检查方法，不代表已完成实测或已有指标结论。

| 检查项 | 需要回答的问题 | 建议保留的证据 |
|--------|----------------|----------------|
| 场景与边界 | 谁在什么情况下使用？哪些请求不支持？ | 场景说明、支持与不支持清单 |
| 测试样例 | 是否覆盖常见任务、模糊输入、信息缺失和异常请求？ | 固定输入、预期结果、样例分类 |
| 回答质量 | 是否正确、完整，能否帮助用户完成任务？ | 评分标准、逐条结果、失败案例 |
| 知识依据 | 关键结论能否追溯来源？无依据时是否说明不确定？ | 来源片段、引用核对记录 |
| 操作可靠性 | 工具调用是否成功？失败或重复操作如何处理？ | 调用记录、错误原因、恢复结果 |
| 人工兜底 | 超出能力范围时，能否清晰提示并转交人工？ | 触发条件、交接信息、处理路径 |
| 体验与成本 | 等待时间、操作步骤和单次任务成本是否可接受？ | 耗时记录、步骤数、成本口径 |

**指标口径**：任务成功率 = 达到预先约定成功标准的任务数 ÷ 评测任务总数。报告比例时同时记录样本数、测试日期、模型或方案版本，避免脱离测试条件比较数字。

**迭代记录模板**：问题现象 → 失败样例 → 原因假设 → 修改方案 → 同批样例复测 → 结论与待验证项。样例不足时先记录观察，不把小样本结果直接当作整体效果。
